# Madrid Voice 第一版评估协议v1.1：缩小人工标注范围

2026-10-17。为降低用户人工标注负担，第一版改为**30条试标＋20条开发＋30条独立测试**。替代v1.0协议的样本数量和工作量要求，不改主题、情绪或指标定义。旧协议、300条原分配和原哈希保留。

## 范围变更与选择规则

- 试标：已有MV001—MV030，含AI辅助复核，只用于指南和开发。
- 开发：已有随机顺序中的DV001—DV020，由用户完成并在聊天中确认7个标签修改；1处不连续引文仅重新分段，保留原文。
- 测试：在已冻结、已随机化的100条测试分配中取TS001—TS030，选择不读取正文、标签或模型输出来挑样本。ID不重新随机生成、不转移开发数据到测试。
- 原DV021—DV170（150条）及TS031—TS100（70条）暂缓，第一版不要求用户填写，也不把空白算absent。

活跃80条继续满足房源、已识别文本簇、传递连接组的隔离。数据源、时间窗、最初10,000条文本上限不变。范围缩小是标注负担的决定，不是为了得到更好的分数。

## 保持不变的规则

标注标准继续使用ANNOTATION_GUIDE_ES_v1.0.md。EVALUATION_PROTOCOL_v1.0.md中对提及、负面内容（negative或mixed）、逐类情绪、TP/FP/FN、Precision/Recall/F1、分母为0时NA、弃答和重复计数的定义继续有效。所有实际评估必须在用户完成30条测试后进行，不得将开发集诊断称为独立测试结果。

开发集完成后再固定方法、代码、配置、模型、预测与指南的指纹。已有第三阶段基线若保持不变，明确写“原版本未调参”；不声称通过训练或校准提高效果。模型预测在测试标注前保存，不因测试标签而修改。只有冻结记录校验通过才生成测试工作簿。

测试用户独立标注，不显示模型预测；不会在标注前让AI对这30条给答案。遇到语义不确定可用指南允许的incierto，不强迫确定判断。测试提交后的格式检查和有来源的修订须留档，不按模型答案改人工标签。测试结果一旦用于改进方法，同一测试集不能再宣称未见过。

## 小样本限制

仅30条测试非常有限，某些主题可能没有负例。各标签必须展示支持数、预测数及TP/FP/FN，分母为0记NA；正例不足10条只作描述，不判断模型优劣。不得只展示总体准确率，也不承诺六主题都能可靠比较。

开发和试标只有一位人工标注者，并接受过AI解释，不能报告多人一致率。这80条采用每组最多一条的既定选择方式，不代表全市所有住客或评论。不能用其比例推算订单、入住率、收入提升或因果影响。

本协议固定后如再改变样本或定义，另存新版本并解释原因，不覆盖历史文件或隐藏失败结果。
